# Head intervention and portable predictor

This study constructs each head from a newly initialized native YOLO26n detector; it never reuses the source detector's head weights. The inherited trunk is initialized from the single verified source trunk (the local synthetic tests use a randomly initialized trunk) and remains frozen in evaluation mode, including all normalization buffers. At each of the twelve second-unit sites—box and classification units, three feature scales, and both native one-to-many and one-to-one branches—the native arm retains its original unit, `independent_k2` replaces it with two independently registered but initially equal copies, and `shared_k2` invokes one identical module object twice. The shared module's BatchNorm therefore receives two sequential updates per forward, while each independent copy receives one; no cross-scale or cross-branch ties are introduced. Native decoding, top-k selection, and the complete dual-branch training loss interface remain native.

All arms use the same predictor boundary: frozen trunk inference in FP32 with autocast disabled, followed by a feature-map FP16 roundtrip and conversion back to FP32 before the native head. `forward_images`, `forward_features`, and deployment call the same quantization function; persisted FP16 features are promoted to FP32 and pass through that same function. The policy identifier `fp32_fp16_fp32_v1` is serialized with every portable checkpoint. There is no unquantized deployment path or selectable quantization variant. Any online/cache equivalence claim is limited to the same producer GPU and probe inputs; bitwise equality across different GPUs is not assumed.

Portable checkpoints contain only native-head named tensors plus a strict allowlisted JSON configuration and sanitized source-trunk receipt; the shared sanitized trunk artifact is a separate tensor-only container. Production loading requires its path and verifies the file SHA256 against `trunk_artifact_sha256` in that receipt before deserializing. In-memory trunk mappings require the explicit synthetic-fixture option and are used only by tests; real-study/public commands must use the verified path form. Loading constructs the requested head topology, validates the excluded-head-index-23 trunk container, then checks head names, shapes, dtypes, and duplicate state entries for shared storage before copying head weights. Resume loading validates head tensor dtype/topology and a nonnegative integer epoch before changing optimizer or head state. Resume helpers keep model and optimizer tensors separate from private source model objects. The source trunk's pre-exposure is disclosed: it was trained from scratch on the same 11,629 COCO training images for 80 epochs with the source native augmentation. This is a conditional head-refinement comparison, not independent-trunk or scratch few-shot generalization. No EMA is used.

Image size is an explicit positive multiple of 32 (512 or 640 are supported); the main-study resolution is selected technically before the main run and is not inferred from outcome data. Tests use only synthetic tensors and synthetic receipt values. They produce no study results and do not access source checkpoints, data, holdout annotations, or external services.

## Post-freeze implementation corrections

The frozen main recipe is SHA256 `3db46e027e40eefde310b3dc35e5c0318e2613993f153ff7dfcd8533e37c9ff0`: five paired head seeds, three arms, 40 fixed epochs, evaluation every five epochs, 512-pixel inputs and batch 32. The following implementation repairs were made after that freeze and before any holdout prediction or annotation reading; they are not hyperparameter searches. Each run records its actual source revision separately from the frozen recipe's original revision.

- **Windows ledger I/O:** cooperative locked reads and bounded atomic-replace retries prevent a concurrent reader from denying replacement of the accounting JSON. Exclusive lock creation also waits through transient access denial under the existing lock deadline; persistent denial fails closed without removing or bypassing a lock. A supervisor-side lock-creation denial interrupted seed-11/independent_k2 after committed epoch 30; the failed allocation remains charged, and recovery must preserve that checkpoint's state and the original fit. Failed allocations remain charged in full. Interrupted runs resume from committed epoch checkpoints with their saved optimizer, loss-schedule and RNG state; partial uncommitted epochs are discarded, and the original 40-epoch target is retained. No bitwise CUDA-resume equivalence is claimed.
- **Annotation heap lifetime:** the filtered original dev/probe ground truth is JSON-roundtripped before releasing the full source dictionary. This detaches retained bbox values from segmentation-sized allocator arenas without changing crowd, area, category or bbox values. Synthetic payload-equality and runtime memory evidence verify this repair.
- **Native signed-box compatibility:** YOLO26's direct regressor can emit finite inverted endpoints, including above-threshold detections. The initial adapter incorrectly rejected those outputs, interrupting native-arm evaluation. Pinned Ultralytics 8.4.177 applies confidence/top-k selection, clips coordinates independently, and exports signed width/height without swapping endpoints or rejecting those rows (`nn/modules/head.py`, `utils/nms.py`, `utils/ops.py`, `models/yolo/detect/val.py`). The corrected common adapter preserves these detections and passes their signed dimensions unchanged to pycocotools 2.0.11. `COCO.loadRes` computes signed area; `COCOeval` applies its own matching and area-ignore rules. We neither drop inverted detections nor repair their geometry: doing so can change AP. A synthetic negative-dimension oracle matches direct COCOeval, including a false positive with two negative dimensions. Nonfinite outputs and invalid image/category IDs still fail closed. This applies identically to all arms and all evaluation cohorts.

After the supervisor interruption, the RTX 5070 Ti epoch-30 recovery received a new 1,200-second reservation. Subsequent full fits on that GPU receive 3,600-second reservations instead of the original 4,500-second forecast; this operational cap uses observed technical wall times, not accuracy. The RTX 3060 retains its 6,000-second per-fit cap. Prior reservations are never refunded, and only completed 40-epoch fits qualify for the final matrix; no shortened fit is substituted.

These corrections do not change the trunk, head topology, loss, optimizer, data cohorts, seed pairing, epoch target, checkpoint-selection rule or feature policy. The initial seed-11/native and seed-22/native attempts were interrupted; their records are retained and their resumed runs must be distinguished from uninterrupted runs in operational timing. The signed-box diagnosis used only an already-trained native checkpoint and the declared dev cache, not holdout data; it is not evidence for a head-sharing benefit.

## Footprint measurement plan

Declared before final measurements: benchmark the selected seed-11 triplet on the RTX 5070 Ti and the selected seed-22 triplet on the RTX 3060, each at batches 1 and 32. These are representative trained checkpoints, not five independent footprint replications. All fifteen selected checkpoints still require final accuracy evaluation. Compare arms within each GPU/batch/policy; do not pool latencies across GPUs as matched samples.

FP32 inference uses zero-valued image tensors at the frozen 512-pixel resolution, five warmups and twenty synchronized repetitions. Full-detector timing includes the frozen trunk, common feature quantization and both native branches; head timing supplies common quantized features and includes the head's conversion boundary. Image loading, preprocessing and checkpoint/cache I/O are excluded from latency. ConvMAC accounting includes every executed convolution, including repeated shared calls, but excludes non-convolution operations; parameter bytes and ConvMACs are not speed or VRAM measurements.

Report separate PyTorch peak allocated/reserved bytes and their baselines in fresh measurement processes. The cached-feature training probe repeats one complete seed-ordered epoch-zero batch for a native BF16 warmup/optimizer step and a measured second step; it does not save changed weights. This brief probe is not the uninterrupted main-fit peak. Neither an unused image tensor during cached training nor an extra cached feature set during full inference belongs in the measured allocation. Serialized weight-file bytes are measured independently from unique tensor storage.

Official validation images may be acquired in advance. Validation annotations stay sealed, and no validation predictions or scoring occur until all fifteen development-selected checkpoint identities have been frozen. Holdout receipts must preserve that chronology; acquisition is not claimed to be prediction or evaluation.
